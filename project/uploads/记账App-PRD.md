## 1. 产品概述

### 1.1 一句话介绍

一个**不需要注册、没有广告、数据全在本机**的个人记账 App。支持三种记账方式：打字、说话、上传支付截图，目标是让记一笔账不超过 10 秒。

### 1.2 要解决的问题

市面上的记账 App（随手记、鲨鱼记账等）普遍存在三个问题：必须注册账号、广告和会员弹窗多、数据要上传到别人的服务器。而大多数人放弃记账的真正原因只有一个——**记一笔账太麻烦了**。

「简记」的解法是把"记一笔"这个动作压缩到极限：

1. **打字记**：打开就是数字键盘，输金额、点分类、完成。
2. **说话记**：按住按钮说"昨天打车花了 23 块"，App 自动识别出金额、分类、日期。
3. **截图记**：把微信/支付宝的付款成功截图丢给 App，自动识别出金额和商家。

### 1.3 产品目标（第一版）

这是个人项目，目标定得实际一点：

- 自己能坚持用满 30 天不弃坑（这是最重要的验证）。
- 文本记一笔账 ≤ 10 秒，语音记一笔 ≤ 5 秒。
- 从零学 Swift 开始，3～4 个月内在自己手机上跑起来完整版。

### 1.4 明确不做什么（第一版范围外）

写清楚"不做什么"和写清楚"做什么"一样重要，能防止你半路加需求把自己拖死：

- ❌ 不做多人/家庭共享账本
- ❌ 不做自动同步银行卡/信用卡账单
- ❌ 不做服务器和账号系统（数据只存本机，iCloud 同步放到远期）
- ❌ 不做 iPad / Apple Watch / 桌面小组件（先把 iPhone 主流程做好）
- ❌ 不做记账提醒推送

## 2. 目标用户

### 2.1 用户画像

**画像 A：想理财的年轻上班族（主要用户）**
25～35 岁，用微信/支付宝付款，每天消费 3～8 笔。曾经下载过记账 App 但一周后就放弃了，原因是"每笔都要手动填太烦"。他最高频的场景是：付完款顺手截个图，晚上想起来再补记。→ 这个人最需要**截图记账**。

**画像 B：不爱打字的人**
开车的、做饭的、走路的时候突然想起有一笔没记。掏出手机打字不方便，说一句话最快。→ 这个人最需要**语音记账**。

**画像 C：你自己**
开发者本人。既是用户又是测试员，每个功能做完先自己用一周。

### 2.2 核心使用场景

| 场景 | 用户行为 | 对应功能 |
|---|---|---|
| 刚在便利店扫码付了 15 元 | 打开 App → 输 15 → 点"餐饮" → 保存 | 文本记账 |
| 走在路上想起早上打车没记 | 按住麦克风说"早上打车 23 块" | 语音记账 |
| 晚上翻相册看到 3 张付款截图 | 选中截图导入，逐条确认 | 图片记账 |
| 月底想知道钱花哪了 | 打开"图表"页看分类饼图 | 统计报表 |
| 发现有一笔记错了 | 在明细里点开，改金额或删除 | 编辑/删除 |

## 4. 核心功能详细说明

### 4.1 F1 文本记账（P0）

**入口：** 底部标签栏正中间的大号「＋」按钮，从任何页面一键可达。

**流程：**

```
点「＋」 → 弹出记账页（默认支出）
  ① 顶部切换：[支出 | 收入]
  ② 分类网格：图标 + 名字，点选（默认选中"其他"）
  ③ 金额区：大字号显示，下方自定义数字键盘（0-9、小数点、删除）
  ④ 可选项：备注（一行文字）、日期（默认今天，可改）
  ⑤ 点「完成」→ 保存 → 页面关闭 → 明细列表顶部出现这笔账
```

**规则细节（开发时容易漏的点）：**

- 金额最多 2 位小数，最大 999999.99，不允许 0 或负数。
- 金额在代码里必须用 `Decimal` 类型，**绝对不要用 `Double`**（Double 存 0.1 会有精度误差，记账 App 的大忌，详见 9.3）。
- 日期选择器只允许选今天及以前（不允许记未来的账，第一版从简）。

**验收标准（做到这些就算完成）：**

- [ ] 从点「＋」到保存成功，全程不超过 4 次点击。
- [ ] 保存后杀掉 App 重开，数据还在。
- [ ] 输入非法金额（如 0、连续两个小数点）时无法保存。

### 4.2 F2 账单明细列表（P0）

**首页主体**。按天分组的列表，每天一个小节：

```
── 7月3日 周五        支出 ¥68.50 ──
🍜 餐饮   午饭麻辣烫              -25.00
🚇 交通                          -8.50
🛍 购物   给猫买罐头              -35.00
── 7月2日 周四        支出 ¥120.00 ──
...
```

- 每行显示：分类图标、分类名、备注（没有则不显示）、金额（支出黑色带负号，收入绿色带正号）。
- **点一行** → 进入详情页，可修改任意字段。
- **左滑一行** → 出现红色"删除"按钮，删除前弹确认框。
- 列表为空时显示引导插画 + "记下第一笔账"按钮（空状态设计，新手常忘）。
- 顶部固定一张月度卡片：`7月 · 支出 ¥1,234.50 · 收入 ¥8,000.00`，左右滑动可切换月份。

### 4.3 F5 语音记账（P1）— 核心卖点之一

**入口：** 记账页里的「🎤」按钮，或长按底部「＋」直接进入。

**交互流程：**

```
按住🎤说话（显示声波动画 + 实时转出的文字）
  → 松手，结束录音
  → App 解析文字，弹出【确认卡片】：
     ┌─────────────────────────┐
     │ 识别原文：昨天打车花了23块  │
     │ 金额：¥23.00     [可点改]  │
     │ 分类：🚇 交通    [可点改]  │
     │ 日期：7月2日     [可点改]  │
     │ 备注：打车                │
     │      [取消]  [确认记账]    │
     └─────────────────────────┘
```

**关键设计原则：语音和图片识别的结果永远不直接入库，必须经过用户确认。** 识别是会出错的，宁可多点一下，不能记错账。

**解析规则（第一版用简单的关键词规则，不用 AI）：**

从识别出的文字里按规则抽取三个信息：

1. **金额**：正则匹配数字，如 `23`、`23.5`、`23块5`。第一版只支持阿拉伯数字，"二十三块"这种中文数字先不做（写进 P2）。
2. **分类**：关键词映射表，命中哪个词就归哪类：

| 分类 | 触发关键词（示例） |
|---|---|
| 餐饮 | 吃、饭、早餐、午饭、晚饭、外卖、奶茶、咖啡 |
| 交通 | 打车、地铁、公交、滴滴、加油、停车 |
| 购物 | 买、淘宝、京东、拼多多 |
| 娱乐 | 电影、游戏、KTV |
| 医疗 | 药、医院、挂号 |
| （无命中） | 归入"其他" |

3. **日期**：识别"今天/昨天/前天"，没说就默认今天。

**失败兜底：** 如果连金额都没解析出来，确认卡片的金额栏留空并自动弹出数字键盘让用户手填——语音失败要能无缝退化成手动记账，而不是弹个报错让用户重来。

**技术依赖与权限：** 用苹果自带的 Speech 框架（`SFSpeechRecognizer`，中文 locale 为 `zh-CN`），优先启用本地识别（`requiresOnDeviceRecognition = true`，支持时不联网、更隐私）。需要在项目配置里声明两个权限文案：麦克风（`NSMicrophoneUsageDescription`）和语音识别（`NSSpeechRecognitionUsageDescription`），首次使用时系统会弹窗向用户要授权，拒绝后要显示引导去设置里打开的提示。

**验收标准：**

- [ ] 说"午饭花了25"，卡片正确显示 ¥25.00 / 餐饮 / 今天。
- [ ] 说一句完全无关的话（"今天天气不错"），卡片金额留空、弹键盘，不崩溃。
- [ ] 拒绝麦克风权限后，点🎤显示去设置开权限的引导，不闪退。

### 4.4 F6 图片记账 / OCR（P1）— 核心卖点之二

**入口：** 记账页里的「🖼」按钮 → 打开系统相册选择器，可一次多选（上限 9 张）。

**流程：**

```
选中 1～9 张截图 → 逐张显示"识别中…"
  → 每张生成一个确认卡片（同语音记账的卡片）：
     金额 / 商家（填入备注）/ 时间（填入日期）/ 猜测的分类
  → 用户逐条确认或修改 → 入库
```

**识别与解析规则：**

- OCR 用苹果自带的 Vision 框架（`VNRecognizeTextRequest`），识别语言设为简体中文 + 英文，`recognitionLevel = .accurate`。**全程本地计算，图片不会离开手机**——这一点要写在界面上，是隐私卖点。
- **金额**：在识别结果里找形如 `¥25.00`、`-25.00` 的文本；微信/支付宝截图里金额通常是字号最大的一行，Vision 会返回每段文字的位置框（bounding box），**取"长得像金额的候选里、文字框最高（字最大）的那个"**，命中率会高很多。
- **商家**：找"商户全称""收款方""付款给 XX"等关键词的下一段文字，填入备注。
- **时间**：匹配 `2026年7月3日 12:30` 或 `2026-07-03` 格式；找不到就默认今天。
- **分类**：拿商家名过一遍 4.3 的关键词表（如商家名含"餐饮/咖啡"→ 餐饮）。

**风险提示：** 微信/支付宝的截图版式会随版本更新变化，规则可能失效。所以：① 确认卡片必须存在且好改；② 把匹配关键词写成代码里集中的一张配置表，改版了只改表不动逻辑；③ 原始识别文字存入账单的 `rawText` 字段，方便日后排查为什么识别错了。

**加分项：** 用 SwiftUI 的 `PhotosPicker`（PhotosUI 框架）选图，它在独立进程里运行，**不需要申请相册权限**，用户体验和隐私都更好——新手很容易不知道这一点而去申请整个相册的读取权限。

**验收标准：**

- [ ] 一张标准微信付款成功截图，金额识别正确率肉眼可接受（自己拿 20 张真实截图测）。
- [ ] 选一张风景照（没有任何金额），卡片金额留空，不崩溃。
- [ ] 断网状态下识别照常工作（证明是本地 OCR）。

### 4.5 F7 统计图表（P1）

「图表」标签页，默认显示本月，顶部可切换月份：

1. **分类占比饼图**（甜甜圈样式）：本月各支出分类的金额占比，点扇区高亮并显示该分类金额；下方按金额从大到小列出分类排行。
2. **每日支出趋势**：本月每天的支出柱状/折线图，一眼看出哪天花超了。
3. 顶部三个数字：本月支出、本月收入、结余（收入 − 支出）。

用苹果官方 **Swift Charts** 框架实现：饼图用 `SectorMark`（iOS 17+），趋势用 `BarMark`/`LineMark`。不需要任何第三方库。

### 4.6 F3/F8 分类（P0 内置，P1 自定义）

**内置分类（写死在代码里的初始数据，首次启动时插入数据库）：**

- 支出：🍜餐饮、🚇交通、🛍购物、🧻日用、🎮娱乐、💊医疗、🏠住房、📦其他
- 收入：💰工资、🧧红包、📈理财、📦其他

图标全部用苹果自带的 **SF Symbols**（免费图标库，Xcode 里直接用名字调用，如 `fork.knife`、`car.fill`），不用自己找图。

**自定义分类（P1）：** 设置页里可新增分类（选名字 + SF Symbol 图标 + 颜色）、改名、排序、删除。**删除分类时，该分类下已有的账单自动归入"其他"，不许连账单一起删。**

## 5. 界面 UI 设计

### 5.1 信息架构（App 一共有哪些页面）

```
TabBar（底部标签栏，3 个标签 + 1 个悬浮按钮）
│
├── 📋 明细（首页）
│     ├── 月度汇总卡片
│     ├── 按天分组的账单列表
│     └── → 账单详情/编辑页
│
├── ➕ 记一笔（正中悬浮大按钮，点击弹出，长按直接进语音）
│     ├── 键盘输入（默认）
│     ├── 🎤 语音记账 → 确认卡片
│     └── 🖼 截图导入 → 确认卡片（可多条）
│
├── 📊 图表
│     ├── 月份切换
│     ├── 支出/收入/结余
│     ├── 分类饼图 + 排行
│     └── 每日趋势图
│
└── ⚙️ 设置
      ├── 分类管理（P1）
      ├── 月度预算（P2）
      ├── 导出 CSV（P2）
      ├── iCloud 同步开关（P2）
      └── 关于
```

### 5.2 设计原则（新手照着做不会丑）

1. **全部用系统组件**：`TabView`、`List`、`NavigationStack`、系统字体（SF Pro）。苹果的默认样式已经很好看，第一版不要自己画花哨控件。
2. **一个主题色**：建议橙色系（记账 = 温暖、活力），支出用主文字色，收入统一用绿色。深色模式用系统语义颜色（如 `Color.primary`、`.secondary`）自动适配，别写死黑白。
3. **大拇指原则**：最高频操作（记一笔）放在屏幕底部中央，单手可达。
4. **空状态都要设计**：无账单、无搜索结果、权限被拒，每种都要有提示文案，不能白屏。
5. **动效克制**：保存成功用一个轻微的触感反馈（Haptic）+ 列表新行淡入即可。

### 5.3 关键页面元素清单

**记账弹出页（最重要的页面）：**

| 区域 | 元素 | 说明 |
|---|---|---|
| 顶部 | 支出/收入分段控件 | `Picker(.segmented)` |
| 上半 | 分类网格 | `LazyVGrid`，4 列，选中态有色块 |
| 中部 | 金额大字 | 等宽数字字体，空时显示灰色 `0.00` |
| 中下 | 备注输入框 + 日期按钮 | 一行放下 |
| 下半 | 自定义数字键盘 | 4×4 网格：1-9、.、0、⌫，右侧竖长「完成」键 |
| 键盘上方 | 🎤 和 🖼 两个入口按钮 | 通向语音/图片记账 |

**确认卡片（语音/图片共用）：** 半透明遮罩 + 居中卡片，字段全部可点击修改，底部「取消 / 确认记账」两个按钮。多张图片时卡片可左右滑或"确认并看下一张"。

## 6. 数据模型与存储

### 6.1 为什么选 SwiftData

**SwiftData 是苹果官方的本地数据库框架（iOS 17+）**，你可以把它理解成"一个自动帮你把 Swift 对象存到手机里的工具"。选它的理由：不用装任何第三方库、和 SwiftUI 是原生搭档（数据一变界面自动刷新）、以后想加 iCloud 同步只需极少改动、教程资料多。新手不要碰 Core Data（老且难）或自己写 SQLite（重复造轮子）。

### 6.2 数据表设计

一共只有两张表。**Transaction（账单）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 唯一标识，自动生成 |
| amount | Decimal | 金额，恒为正数 |
| isExpense | Bool | true=支出，false=收入 |
| category | Category（关系） | 指向所属分类 |
| date | Date | 账单发生日期（用户可改） |
| note | String | 备注，可为空字符串 |
| source | String（枚举） | "manual" / "voice" / "image"，用于统计三种入口的使用率 |
| rawText | String? | 语音识别原文或 OCR 全文，排错用，可为空 |
| createdAt | Date | 记录创建时间，自动生成 |

**Category（分类）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 唯一标识 |
| name | String | 分类名，如"餐饮" |
| symbolName | String | SF Symbol 图标名，如 "fork.knife" |
| colorHex | String | 颜色，如 "#FF9500" |
| isExpense | Bool | 支出分类还是收入分类 |
| sortOrder | Int | 排序 |
| isBuiltin | Bool | 内置分类不许删，只许自定义的删 |

### 6.3 代码长什么样（给你一个直观感受）

```swift
import SwiftData

@Model
final class Transaction {
    var id: UUID = UUID()
    var amount: Decimal = 0        // 金额永远用 Decimal！
    var isExpense: Bool = true
    var category: Category?
    var date: Date = Date()
    var note: String = ""
    var source: String = "manual"  // manual / voice / image
    var rawText: String?
    var createdAt: Date = Date()

    init(amount: Decimal, isExpense: Bool, category: Category?,
         date: Date = .now, note: String = "", source: String = "manual") {
        self.amount = amount
        self.isExpense = isExpense
        self.category = category
        self.date = date
        self.note = note
        self.source = source
    }
}
```

在界面里读数据只要一行 `@Query(sort: \Transaction.date, order: .reverse) var transactions: [Transaction]`，SwiftData 会自动查库并在数据变化时刷新界面——这就是选它的原因。

### 6.4 存储原则

- **本地优先**：所有数据存在手机上，删 App 数据即消失（要在"关于"页写明，P2 做 iCloud 后解决）。
- **截图不整张入库**：识别完只存解析出的文字结果和 `rawText`，不把图片文件塞进数据库（体积爆炸）。想留凭证是 P2 需求，届时存缩略图文件、库里只存路径。

## 9. 新手最容易踩的 4 个坑（提前预警）

### 9.1 语音/OCR 识别结果不可靠

这是本项目最大的技术风险。对策已内置在设计里：**永远弹确认卡片，永远保留手动修改，识别失败退化为手动输入**。不要追求全自动。

### 9.2 支付截图版式会变

微信/支付宝改版可能让解析规则失效。对策：关键词写成集中配置表；`rawText` 留档排查；确认卡片兜底。

### 9.3 金额精度

用 `Double` 存钱，`0.1 + 0.2` 会得到 `0.30000000000000004`。**全链路用 `Decimal`**，显示时用 `NumberFormatter`/`.formatted(.currency(code: "CNY"))` 格式化。这条写三遍都不过分。

### 9.4 开发环境的现实

- 必须有一台 **Mac**，装 **Xcode 16+**（免费）。
- **模拟器就能开发全部功能**：模拟器可用 Mac 的麦克风测语音，把截图拖进模拟器相册就能测 OCR。
- 免费 Apple ID 可以把 App 装到自己 iPhone 上（7 天签名过期需重装）；付费开发者账号（$99/年）只在你想长期真机使用或上架 App Store 时才需要。
